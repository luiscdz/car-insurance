### REQ-008

# REQ-008: Plan list built from content

The plan list step of the country's wizard shows the plans configured in Strapi for that country that are both published and active, in configured order. Each plan shows its name, short description, base price, coverages and benefits, and the plan marked as recommended is distinguished. The plan list copy comes from the country's content in Strapi. Plan content is validated before use (P3), and a change published in Strapi is visible on the next load of the application without a code change or a deployment (P2). No behavior depends on code that names a specific country (P1, ADR-001).

Acceptance: AC-036, AC-037, AC-038, AC-039, AC-040, AC-041.

#### AC-036

# AC-036: Only the country's published, active plans, in configured order

Requirement: REQ-008.

Given Colombia and Chile have plans in Strapi, some published and active, some published but not active, and some saved only as drafts
When the person who completed the form steps reaches the plan step at `/co`
Then exactly the plans of Colombia that are both published and active are shown, in ascending configured order
And no plan of Chile, no inactive plan and no draft plan is shown
And the same holds for `/cl` with Chile's plans.

Plans with the same order value are shown in a stable order across loads: ascending creation order in Strapi (as AC-004).

**Verification:** End-to-end test for Colombia and Chile with the seed data, plus an inactive plan and a draft plan created for each country by the test setup with a test-only credential that never reaches the browser; unit test with fixtures for both countries, including equal order values.

#### AC-038

#### AC-041

# AC-041: Plan content validation

Requirement: REQ-008.

Given the published, active plans received from Strapi for the country
Then each plan is valid only when it has:
- a name and a short description that are not blank;
- a base price that is a whole number greater than zero;
- a currency equal to the currency code of the country's entry;
- a whole-number order;
- at least one coverage, each with a name that is not blank and, optionally, a highlighted value that is not blank when present;
- zero or more benefits, each a text that is not blank;
- a recommended flag that is true or false, where an absent flag means false
When any received plan is not valid
Then the country's content is invalid and AC-017 applies: the fallback message is shown and no part of the wizard is shown.

Plans that are inactive or saved only as drafts are not received and therefore never make the content invalid.

**Verification:** Unit test of the shared content schemas with valid and invalid plan fixtures for both countries (each rule above broken once, including a base price of 0, a negative and a non-whole base price, and a currency that differs from the country's).

### REQ-009

# REQ-009: Prices and the simulated final price

Prices are whole amounts in the country's currency and are formatted with the currency code and formatting locale of the country's entry in Strapi (ADR-001). The final price of the chosen plan is obtained from the stateless price-quote endpoint, which applies the simulated rule documented in this capability to the plan's published base price and to the policyholder's and the vehicle's ages derived from the step 1 data. Only those ages, the plan and the country leave the browser for this purpose; no entered value is sent, stored or logged (P5), and the browser uses no token (P4).

Acceptance: AC-042, AC-043, AC-044, AC-045, AC-046, AC-047, AC-066.

#### AC-042

# AC-042: Prices in the country's currency and format

Requirement: REQ-009.

Given a country whose entry in Strapi has currency code C and formatting locale L (seed: Colombia COP and es-CO; Chile CLP and es-CL)
When any price is shown on the plan step, base or final
Then it is formatted with the browser's `Intl` number formatting for locale L and currency C: the currency symbol that formatting gives for L, the thousands separator of L and no decimal digits
And with the seed, a base price of 1200000 is shown in Colombia as `$ 1.200.000` and a base price of 350000 in Chile as `$350.000`, with the spacing between symbol and number that `Intl` produces for each locale.

Prices are whole amounts of the currency; no decimal part is ever shown. No formatting rule in code names a country, a currency or a locale.

**Verification:** Unit test of the price formatting function with fixtures for both countries (compared with the output of `Intl` for the same locale and currency); end-to-end test checking one seeded base price in each country.

#### AC-043

# AC-043: Documented simulated price rule

Requirement: REQ-009.

This criterion documents the simulated price rule. It is a simulation (P5), not a real rating, and it is the same for every country: no value of the rule comes from or differs by country.

Given a plan with base price B (a whole amount of the country's currency), the policyholder's age A and the vehicle's age V, both in whole years (AC-044)
When the final price is computed
Then it is B × (1 + vehicle adjustment + age adjustment), computed exactly and rounded to the nearest whole amount, with halves rounded up, where:
- vehicle adjustment is 0 when V ≤ 5, 0.10 when 6 ≤ V ≤ 10 and 0.20 when V ≥ 11 (a vehicle of next year's model has V = −1);
- age adjustment is 0.15 when A ≤ 25, 0 when 26 ≤ A ≤ 64 and 0.10 when A ≥ 65;
- an input that is not available (AC-044) contributes 0.

Examples, with fictitious values:

| B | A | V | Final price |
| --- | --- | --- | --- |
| 1000000 | 40 | 3 | 1000000 |
| 1000000 | 22 | 8 | 1250000 |
| 1000000 | 70 | 15 | 1300000 |
| 350000 | 25 | 6 | 437500 |
| 350000 | 26 | 5 | 350000 |
| 333333 | 30 | 10 | 366666 |
| 12345 | 30 | 10 | 13580 |
| 520000 | not available | 11 | 624000 |

**Verification:** Unit test of the rule as a pure function, with the examples above and every bracket boundary (V = 5, 6, 10, 11; A = 25, 26, 64, 65), V = −1 and unavailable inputs.

#### AC-044

# AC-044: Inputs of the price rule

Requirement: REQ-009.

Given the country's form fields in Strapi
Then a field can be marked as the policyholder's birth date for pricing, or as the vehicle year for pricing, and no other pricing input exists
And in each country at most one field carries each mark; the birth date mark is allowed only on a date field and the vehicle year mark only on a number field
And a mark on a field of another type, or the same mark on two fields of the country, makes the country's content invalid (AC-017).

Given the stored values of the country's completed form steps
When the inputs of the rule are derived on the person's device
Then the policyholder's age A is the number of whole years completed on the device's current date since the value of the field marked as birth date, computed as for the legal age of AC-014 (a 29 February birthday is reached on 1 March in years that are not leap years)
And the vehicle's age V is the device's current year minus the value of the field marked as vehicle year
And when no field carries a mark, or the marked field has no stored value, that input is not available.

The marks are configuration: no code names a field, a country or a step to find the inputs.

**Verification:** Unit test of the input derivation with a fixed date and fixtures for both countries (Colombia with both marks in one form step, Chile with the marks in different form steps, a country with no marks); unit test of the shared content schemas with a duplicated mark and a mark on a field of the wrong type.

#### AC-045

# AC-045: Final price of the chosen plan

Requirement: REQ-009.

Given the plan step shows the country's plans, each with its base price
When the person chooses a plan
Then the final price of that plan is requested from the price-quote endpoint with the inputs of AC-044
And while it is being obtained, the chosen plan shows, in place of its final price, the text configured for that wait, announced to assistive technologies as a status, and no other plan shows a final price
When the final price arrives
Then the chosen plan shows it, formatted as in AC-042 and next to the final price label, in addition to its base price, and the final price is announced as a status.

The endpoint computes the final price with the rule of AC-043 from the plan's base price as published and active in Strapi for that country at the time of the request, never from a price sent by the browser. A plan that does not exist, is not published, is not active or belongs to another country, and inputs that are not whole numbers, get an error answer (AC-047).

**Verification:** Unit test (component) of the waiting and final price states; unit test of the price-quote endpoint (published active plan; unpublished, inactive and other-country plan; malformed inputs); end-to-end test for Colombia and Chile whose step 1 data gives a known adjustment, checking the final price shown.

#### AC-046

# AC-046: Only derived ages leave the browser

Requirement: REQ-009.

Given the person entered their data in the form steps
When the final price is requested
Then the request carries only the country code, the plan's identifier, and the policyholder's age and the vehicle's age when available (AC-044)
And no value entered in a form step, such as the document number, the RUT, the birth date, the license plate, the make or the vehicle year, appears in that request, in any other request sent to Strapi, in the address or in the browser console
And the price-quote endpoint stores nothing (no quote, no inputs, no personal data) and does not log the inputs it receives.

This criterion keeps AC-026 true while the person is on the plan step.

**Verification:** End-to-end test observing the requests, the address and the console on the plan step, for Colombia and Chile; unit test of the price-quote endpoint showing that it writes nothing and logs no input.

#### AC-047

# AC-047: Final price cannot be obtained

Requirement: REQ-009.

Given the person chose a plan
When the final price request fails (network failure or HTTP error status) or its answer is not a whole amount greater than zero
Then the chosen plan shows the price error message from Strapi with its retry action, announced to assistive technologies, and no final price and no technical detail
And the plan stays chosen, and continue does not advance (AC-051)
When the person activates retry
Then the final price is requested again, with the waiting state of AC-045, and is shown if it now arrives.

Choosing another plan replaces the error with the request for the new plan (AC-049).

**Verification:** Unit test (component) of the error and retry; end-to-end test for one country with the price-quote request blocked from the browser, then allowed before retry.

### REQ-010

# REQ-010: Plan selection and navigation

The person chooses exactly one plan. The choice is stored in the country's wizard data when it is made, is kept per country for the life of the browser tab, survives going back, going forward and reloading, and is reconciled with the current plans. The person moves on to the summary step only with a chosen plan whose final price has been obtained for the current step 1 data. Confirming changed step 1 data keeps the choice and requires a new final price. Because the choice is stored when made, the plan step never has unconfirmed values and never asks before leaving.

Acceptance: AC-048, AC-049, AC-050, AC-051, AC-052, AC-053, AC-054, AC-055, AC-056, AC-057.

#### AC-048

When the person chooses a plan

**Verification:** Unit test (component) with fixtures for both countries; end-to-end test for Colombia and Chile choosing one plan and then another.

### REQ-011

# REQ-011: Plan list states

When the country has no published, active plans, the plan step explains that no plans are available. The plans are requested together with the rest of the country's content when the wizard loads, so their loading, unavailable and invalid states are the controlled, announced states of the wizard and never a broken or partial plan list (P3).

Acceptance: AC-058, AC-059.

#### AC-058

# AC-058: No plans available

Requirement: REQ-011.

Given the country has no plan that is both published and active in Strapi (none exist, or they are all inactive or saved only as drafts)

**Verification:** Unit test (component); end-to-end test for one country whose plans are deactivated by the test setup with a test-only credential that never reaches the browser, and restored afterwards.

#### AC-059

# AC-059: Plans loading, unavailable or invalid

Requirement: REQ-011.

Given the person opens any address of a country's wizard
Then the country's published, active plans are requested, filtered by the country, together with the country and its steps
And while any of these requests has not arrived, the loading state of AC-015 is shown
When the plans request fails (network failure or HTTP error status)
Then the unavailable state of AC-016 is shown, and its retry action requests the plans again together with the rest of the content, keeping the data already stored for the country in this tab
When the plans received are not valid (AC-041)

And in none of these states is any step of the wizard, any plan or any partial plan list shown.

**Verification:** Unit test (component) of the three states; end-to-end test with the plans request blocked from the browser.
