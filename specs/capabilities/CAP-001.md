### REQ-001

# REQ-001: Country context

The application serves the quoting wizard in the context of one country, identified by the first segment of the address (`/co`, `/cl`), as decided in ADR-001. The root address lets the person choose among the countries published in Strapi. An address whose country is unknown or not published shows a controlled message instead of a wizard. The theme configured in Strapi for the country is applied, with the default theme as fallback. No behavior depends on code that names a specific country (P1).

Acceptance: AC-001, AC-002, AC-003.

#### AC-001

# AC-001: Country selection at the root address

Requirement: REQ-001.

Given Colombia and Chile are published countries in Strapi
When the person opens the root address of the application
Then they see one choice per published country, labeled with the country name configured in Strapi
And choosing a country opens the first step of that country's wizard at `/{code}` (`/co`, `/cl`)
And a country that is not published is not offered.

The root page's heading and page title are front-end fallback copy in Spanish, because no country content exists yet at that address; apart from them, the page shows only the country names from Strapi.
When the list of countries cannot be loaded or is invalid, the states of AC-016 and AC-017 apply.

**Verification:** End-to-end test (both countries offered; choosing each opens its first step; heading and page title present) and unit test (component) of the root page copy.

#### AC-002

# AC-002: Unknown or unpublished country code

Requirement: REQ-001.

Given the first segment of the address does not exactly match the code of a country published in Strapi (for example `/xx`, `/CO`, or a country saved only as a draft)
When the person opens that address or any address below it
Then they see a fallback message in Spanish stating that the country is not available, announced to assistive technologies, with a link to the country selection at the root address
And no wizard step, field or content of another country is shown.

**Verification:** End-to-end test (`/xx`) and unit test (upper-case code; country absent from the published response).

#### AC-003

# AC-003: Country theme with fallback

Requirement: REQ-001.

Given a country whose entry in Strapi has a valid theme (primary color and accent color as valid color values, and a logo)
When any screen of that country's wizard is shown
Then the elements the design reference assigns to the primary and accent tokens use the country's colors, and the country's logo is shown
When the theme is missing or any of its values is malformed
Then the default theme of the design reference is used and the text placeholder replaces the logo, and the wizard still works.

Layout, components and typography are the same for both countries.

**Verification:** Unit test (valid, missing and malformed theme, fixtures for both countries) and declared manual check of the seeded themes of Colombia and Chile at both reference widths.

### REQ-002

# REQ-002: Form steps built from content

Each form step of the country's wizard is built from its published configuration in Strapi: step title, fields and, for each field, label, type (text, number, select, date, checkbox), required flag, validations, help text, error message, order and, for select fields, options. The wizard's own copy also comes from Strapi. A change published in Strapi is visible on the next load of the application without a code change or a deployment (P2).

Acceptance: AC-004, AC-005, AC-006, AC-007, AC-008.

#### AC-004

# AC-004: Only the country's fields, in the configured order

Requirement: REQ-002.

Given Colombia and Chile have published form steps with different fields in Strapi
When the person opens `/co`
Then the first form step shows, under the step title configured for Colombia, exactly the published fields of that step, in ascending configured order, and no field of Chile or of another step
And the same holds for `/cl` with Chile's configuration.

Fields with the same order value are shown in a stable order across loads (ascending creation order in Strapi).

**Verification:** End-to-end test for Colombia and Chile with the seed data; unit test with fixtures for both countries, including equal order values.

#### AC-005

# AC-005: Field presentation by configured type

Requirement: REQ-002.

Given a published field configured in Strapi
When its form step is shown
Then the field shows its configured label above the control, a `*` marker when it is required, and its configured help text below it when one is configured
And its control matches its type: text gives a text input, number a numeric input, select a list of options (AC-006), date a date input, checkbox a checkbox whose text is the label.

**Verification:** Unit test (component) of every field type, required and optional, with and without help text, with fixtures for both countries.

#### AC-006

# AC-006: Select options from Strapi

Requirement: REQ-002.

Given a select field with options configured in Strapi
When the person opens the list
Then it offers exactly the options configured for that field, each with its configured label, in their configured order
And no option is chosen until the person chooses one.

Example with the seed: the Colombian document type offers "Cédula de ciudadanía" and "Cédula de extranjería"; the make field of each country offers that country's makes.

**Verification:** Unit test (component) and end-to-end test (Colombian document type and the makes of both countries).

#### AC-007

# AC-007: Published configuration change visible on reload

Requirement: REQ-002.

Given the person has opened the wizard of a country
When the business team publishes a new field in a form step of that country in Strapi
And the person reloads the application
Then the new field appears in its configured position, with no code change and no deployment
And likewise, after a reload, a field that was unpublished or deleted no longer appears, and a changed order, label, help text, error message, validation or option is shown as configured
And a field saved only as a draft never appears.

**Verification:** End-to-end test whose setup adds, reorders and unpublishes a field through Strapi with a test-only credential that never reaches the browser.

#### AC-008

# AC-008: Wizard copy comes from Strapi

Requirement: REQ-002.

Given a country
When its wizard is shown
Then every piece of Spanish copy on the screen, other than the front-end fallback copy (the messages of AC-002, AC-016 to AC-018, the loading label of AC-015 and the root page copy of AC-001), comes from that country's content in Strapi, including step titles, field texts, the labels of the continue and back actions, the labels of the progress indicator and the copy of the leave dialog of AC-034
And changing that copy in Strapi changes the screen after a reload.

The browser's own leave confirmation of AC-033 is not part of the application's copy: its text is set by the browser and cannot be customized.

**Verification:** Unit test (component) with fixtures for both countries showing different copy.

### REQ-003

# REQ-003: Field validation

Each field is validated with the validations and the single error message configured for it in Strapi, with inclusive limits and dates relative to the current date on the person's device. A form step cannot be left forward while any of its fields is invalid. The vehicle year and the policyholder's legal age are enforced through these configured validations.

Acceptance: AC-009, AC-010, AC-011, AC-012, AC-013, AC-014.

#### AC-009

# AC-009: Configured error message next to the field

Requirement: REQ-003.

Given a field whose value fails any of its configured validations, including the required flag
When its error is shown (AC-010)
Then the error message configured in Strapi for that field appears directly below the field, with an error icon and text so that color is not the only cue
And the message is programmatically associated with the field and the field is exposed as invalid to assistive technologies
And a field has a single configured error message, shown whichever of its validations fails.

**Verification:** Unit test (component) and end-to-end test for Colombia and Chile.

#### AC-010

# AC-010: When errors are shown

Requirement: REQ-003.

Given a form step
When the person has neither left a field nor tried to advance
Then that field shows no error, even if its value is invalid
When the person leaves the field or tries to advance
Then its error is shown if its value is invalid
When the value becomes valid
Then its error disappears immediately.

**Verification:** Unit test (component).

#### AC-011

# AC-011: The step cannot advance while a field is invalid

Requirement: REQ-003.

Given at least one field of the current form step is invalid
Then the continue action is shown in its disabled style and exposed as disabled to assistive technologies, yet stays focusable
When the person activates it
Then the wizard stays on the same step
And the error of every invalid field is shown
And focus moves to the first invalid field in display order and its error is announced.

When every field becomes valid, the continue action is shown enabled.

**Verification:** End-to-end test for Colombia and Chile and unit test (component).

#### AC-012

# AC-012: Supported validations and inclusive limits

Requirement: REQ-003.

Given a field configured in Strapi with any of the following validations
When the person enters a value
Then the field is valid only if the value satisfies all of them, every limit being inclusive:

- required: a value is present; text made only of spaces, an unchecked checkbox and a select with no option chosen count as empty;
- text: minimum length, maximum length and a pattern that the whole value must match, evaluated on the value without leading or trailing spaces;
- number: minimum value, maximum value and, when configured, whole numbers only;
- date: minimum age in whole years at the current date (AC-014);
- year: a range relative to the current year (AC-013).

A field that is not required and is left empty is valid, and its other validations are not evaluated.

**Verification:** Unit test of each validation at, below and above its limits, with fixtures for both countries.

#### AC-013

# AC-013: Vehicle year limits

Requirement: REQ-003.

Given the current date on the person's device is in year Y
And the vehicle year field is configured with the range from 20 years before to 1 year after the current year (seed of AC-031 and AC-032)
When the person enters a year from Y−20 to Y+1, both included
Then the field is valid
When they enter Y−21 or earlier, Y+2 or later, or a value that is not a whole number
Then the field shows its configured error message and the step cannot advance.

Example: with Y = 2026, 2006 and 2027 are accepted; 2005 and 2028 are rejected. Colombia and Chile behave the same.

**Verification:** Unit test with a fixed current date (Y−21, Y−20, Y+1, Y+2, a decimal) and end-to-end test for Colombia and Chile (one accepted and one rejected boundary computed from the current date).

#### AC-014

# AC-014: Legal age of the policyholder

Requirement: REQ-003.

Given the current date on the person's device is D
And the birth date field is configured with a minimum age of 18 years (seed of AC-031 and AC-032)
When the birth date makes the person 18 or older on D, including a person whose 18th birthday is D
Then the field is valid
When the 18th birthday falls after D, or the birth date is after D
Then the field shows its configured error message and the step cannot advance.

A birth date of 29 February reaches each age on 1 March in years that are not leap years.
Example: with D = 2026-11-23, 2008-11-23 is accepted and 2008-11-24 is rejected. Colombia and Chile behave the same.

**Verification:** Unit test with a fixed current date (the day of the 18th birthday, the day before it, a future date, 29 February) and end-to-end test for Colombia and Chile (one accepted and one rejected date computed from the current date).

### REQ-004

# REQ-004: Content states

While the country's content loads, when Strapi is unavailable, when the content is invalid and when a form step has no fields, the person sees a controlled, announced state and never a broken or partial form (P3). Copy shown before any country content exists is front-end fallback copy in Spanish.

Acceptance: AC-015, AC-016, AC-017, AC-018.

#### AC-015

# AC-015: Loading state

Requirement: REQ-004.

Given content has been requested and has not arrived (the list of countries at the root address, or the country and its steps in a wizard)
When the screen is shown
Then a visible loader is shown
And a Spanish loading label, which is front-end fallback copy, is announced to assistive technologies as a status; the label is not required to be visible
And no field, partial form or continue action is shown.

When the person's system requests reduced motion, the loader stays visible without movement.

**Verification:** Unit test (component) of the loader, the announced label and the reduced-motion variant.

#### AC-016

# AC-016: Strapi unavailable

Requirement: REQ-004.

Given Strapi does not answer or answers with an error (network failure or HTTP error status) when the countries, the country or its steps are requested
When the request fails
Then the person sees a fallback message in Spanish stating that the form could not be loaded, announced to assistive technologies, with a retry action and no technical detail
When the person activates retry
Then the content is requested again and the form is shown if it now loads
And data already stored for the country in this tab is kept.

**Verification:** Unit test (component) and end-to-end test (Strapi requests blocked from the browser).

#### AC-017

# AC-017: Invalid content

Requirement: REQ-004.

Given the content received for the country fails validation, for example: a field without label or error message, an unknown field type, a select field without options, a validation with missing values, a minimum greater than its maximum or an unusable pattern, or a step sequence that breaks ADR-001 (at least one form step, then exactly one plan list, then exactly one summary and payment step as the last step)
When the wizard is loaded
Then the person sees a fallback message in Spanish stating that the form is not available right now, announced to assistive technologies, with no technical detail
And no part of the wizard is shown.

**Verification:** Unit test of the shared content schemas with valid and invalid fixtures for both countries, and unit test (component) of the message.

#### AC-018

# AC-018: Form step without fields

Requirement: REQ-004.

Given a country whose current form step has no published fields
When the person reaches that step
Then the person sees a fallback message in Spanish stating that the form is not available right now, announced to assistive technologies
And the step cannot advance.

**Verification:** Unit test (component).

### REQ-005

# REQ-005: Wizard navigation and data

The person moves forward and back through the country's configured steps. The values of completed steps are kept per country for the life of the browser tab, survive going back and reloading, are reconciled with the current configuration, and never leave the browser during the form steps (P5). Direct entry to a later step leads to the first step that is not complete. Values typed in the current step and not confirmed with continue are not stored, but the person is asked before they are lost by reloading, closing the tab or leaving the wizard; going back to the previous step does not ask.

Acceptance: AC-019, AC-020, AC-021, AC-022, AC-023, AC-024, AC-025, AC-026, AC-033, AC-034, AC-035.

#### AC-019

# AC-019: Advance to the next step

Requirement: REQ-005.

Given every field of the current form step is valid
When the person activates continue
Then the step's values are stored in the wizard data of the country
And the next step in the country's configured order is shown at its own address under the country prefix
And focus moves to that step's heading
And the progress indicator, which lists all the country's steps in configured order with their titles, marks it as the current step (with the seed: three steps for Colombia, four for Chile).

**Verification:** End-to-end test (Chile from "Tus datos" to "Tu vehículo"; Colombia leaving its form step) and unit test.

#### AC-020

# AC-020: Data kept when going back

Requirement: REQ-005.

Given the person completed a form step and moved to a later step
When they go back with the wizard's back action or the browser's back button
Then the previous form step shows every value they entered, including chosen select options and checkbox states, with no error displayed.

The first step of the wizard offers no back action.

**Verification:** End-to-end test for Chile (form step 2 back to form step 1, with both back mechanisms) and unit test of the wizard data store with fixtures for both countries.

#### AC-021

# AC-021: Single advance on repeated activation

Requirement: REQ-005.

Given every field of the current form step is valid
When the person activates continue twice in quick succession (double click or repeated key press)
Then the wizard advances exactly one step.

**Verification:** Unit test (component).

#### AC-022

# AC-022: Reload keeps the step and completed data

Requirement: REQ-005.

Given the person is on a step after completing the previous ones
When they reload the page
Then the same step is shown and the values of every completed step are kept
And values typed in the current step and not yet confirmed with continue are not kept; the person is asked first, as stated in AC-033.

**Verification:** End-to-end test.

#### AC-023

# AC-023: Data per country and per tab

Requirement: REQ-005.

Given the person entered data in the Colombian wizard
When they open the Chilean wizard in the same tab
Then the Chilean form shows none of the Colombian values
And returning to `/co` shows the Colombian values again
When the tab is closed and the wizard is opened in a new tab
Then the forms of both countries are empty.

**Verification:** End-to-end test.

#### AC-024

# AC-024: Direct entry to a later step

Requirement: REQ-005.

Given an earlier step of the country has not been completed with valid data in this tab
When the person opens the address of a later step directly (typed, bookmarked or shared), or the address of a step that does not exist for the country
Then they are taken to the first step that is not complete, with no error displayed.

**Verification:** End-to-end test and unit test.

#### AC-025

# AC-025: Stored data reconciled with the current configuration

Requirement: REQ-005.

Given the tab holds data stored for the country
When the wizard loads a configuration that changed since the data was stored
Then stored values of fields that are no longer published are discarded
And a step whose stored values no longer satisfy the current configuration (a new required field, a changed validation) is treated as not complete: it shows the stored values that still apply, AC-024 applies to later steps, and its errors appear as stated in AC-010 and AC-011.

**Verification:** Unit test of the wizard data store with fixtures for both countries.

#### AC-026

# AC-026: Entered data stays in the browser

Requirement: REQ-005.

Given the person enters values in a form step
When they fill it in, advance or go back
Then the values never appear in the address, in any request sent to Strapi or in the browser console
And they are kept only in the browser's session storage of that tab.

**Verification:** End-to-end test observing the address, the requests and the console, for Colombia and Chile.

#### AC-033

# AC-033: Browser leave confirmation on reload or tab close

Requirement: REQ-005.

Given the current step has unconfirmed values: at least one field whose value differs from the value stored for that step, or from empty when the step was never completed
When the person reloads the page or closes the tab or the window
Then the browser's own leave confirmation is shown, with the text the browser sets (it cannot be customized and does not come from Strapi)
When the person chooses to stay
Then the page, the step and the typed values remain unchanged
When the person chooses to leave
Then the page unloads and the unconfirmed values are lost (AC-022).

Given the current step has no unconfirmed values (nothing typed, or only values equal to the stored ones)
Then reloading or closing shows no confirmation.

The browser shows the same confirmation for any other way of unloading the page, such as typing another address or following a link to another site, because it does not tell these apart from a reload. Browsers that do not support this confirmation, notably Safari on iOS, show none and the unconfirmed values are lost.

**Verification:** End-to-end test in a browser that supports the confirmation, for Colombia and Chile (reload and close with and without unconfirmed values; stay and leave), and unit test of the unconfirmed-values detection.

#### AC-034

# AC-034: Application dialog when leaving the wizard

Requirement: REQ-005.

Given the current step has unconfirmed values (as defined in AC-033)
When the person navigates within the application out of the country's wizard, to the root address or to another country's wizard, for example with the browser's back or forward buttons, including going back from the first step to the root address
Then the application shows its own modal confirmation dialog before the navigation happens, with a title, a message, a stay action and a leave action whose Spanish copy comes from the current country's content in Strapi
When the person chooses stay, or presses Escape
Then the dialog closes, the person remains on the same step at the same address with the typed values intact, and focus returns to the element that had it before the dialog opened
When the person chooses leave
Then the navigation proceeds, the unconfirmed values are discarded, and the data of the country's completed steps is kept (AC-023).

When the dialog opens, focus moves to the stay action; the dialog has a programmatic name and description, can be answered with the keyboard alone and keeps focus inside it until it closes.
Given the current step has no unconfirmed values, no dialog is shown.
Missing dialog copy makes the country's content invalid (AC-017).

**Verification:** End-to-end test for Colombia and Chile (back from the first step to the root; history navigation to the other country; stay, Escape and leave; no dialog without unconfirmed values) and unit test (component) of the dialog.

#### AC-035

# AC-035: Going back to another step of the same wizard does not ask

Requirement: REQ-005.

Given the current step has unconfirmed values
When the person goes back to the previous step with the wizard's back action or the browser's back button, or moves to another step of the same country's wizard through the browser's history
Then no confirmation is shown
And the step they move to shows its stored values (AC-020)
And the unconfirmed values of the step they left are discarded.

**Verification:** End-to-end test for Chile (type in "Tu vehículo", go back with both mechanisms; no dialog; values of "Tu vehículo" not kept) and unit test.

### REQ-007

# REQ-007: Seed content for Colombia and Chile

A fresh start of the project provides published, fictitious content for Colombia and Chile with different step configurations and the identifiers of each country, so both countries can be used and tested from one command.

Acceptance: AC-031, AC-032.

#### AC-031

# AC-031: Seed content for Colombia

Requirement: REQ-007.

Given a fresh start of the project with an empty database
Then Colombia (code `co`, currency COP, locale es-CO) is published with the steps, in order: 1 "Tus datos y tu vehículo" (form), 2 "Elige tu plan" (plan list), 3 "Resumen y pago" (summary and payment)
And its form step contains, in this order and all required:
- Tipo de documento: select with "Cédula de ciudadanía" and "Cédula de extranjería";
- Número de documento: text of 6 to 10 digits;
- Fecha de nacimiento: date with a minimum age of 18 years;
- Placa: text of three letters followed by three digits (example `ABC123`);
- Marca: select with at least three vehicle makes;
- Año del vehículo: whole number from 20 years before to 1 year after the current year;
letters in these formats are accepted in upper or lower case;
each field has a Spanish label, help text and error message, and only fictitious example values are used.

**Verification:** End-to-end test against the seeded stack.

#### AC-032

# AC-032: Seed content for Chile

Requirement: REQ-007.

Given a fresh start of the project with an empty database
Then Chile (code `cl`, currency CLP, locale es-CL) is published with the steps, in order: 1 "Tus datos" (form), 2 "Tu vehículo" (form), 3 "Elige tu plan" (plan list), 4 "Resumen y pago" (summary and payment)

letters in these formats, including the check character K, are accepted in upper or lower case;
each field has a Spanish label, help text and error message, and only fictitious example values are used.

**Verification:** End-to-end test against the seeded stack.
