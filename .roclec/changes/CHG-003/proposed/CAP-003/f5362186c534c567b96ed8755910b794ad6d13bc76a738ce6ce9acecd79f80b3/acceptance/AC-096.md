# AC-096: Leave confirmation while a payment is processed

Requirement: REQ-018.

Given a payment request is being processed on the summary step (AC-078)
When the person reloads the page or closes the tab or the window
Then the browser's own leave confirmation of AC-033 is shown, with the text the browser sets
When the person navigates within the application away from the summary step, to another step of the same wizard, to the root address or to another country's wizard (with the browser's back or forward buttons, since the wizard's own actions are locked)
Then the application's modal dialog of AC-034 is shown before the navigation happens, with the same behavior (focus moves to the stay action; Escape means stay; focus stays inside until it closes; focus returns after stay), and with the title, message, stay label and leave label of the summary copy for leaving while a payment is processed (AC-073)
When the person chooses to stay
Then the summary remains at the same address, still processing, and the answer is applied when it arrives (AC-081, AC-083)
When the person chooses to leave
Then the page unloads or the navigation proceeds, the answer of the abandoned request is ignored, no confirmation is stored, and on return the summary is shown again unpaid with the terms unaccepted; the payment is simulated and stateless, so nothing was charged or recorded.

If the answer arrives while the application's dialog is open, it is applied at once (the confirmation is stored, or the error is shown) and the dialog stays open until the person answers; choosing leave then navigates without asking again, and a stored confirmation stays (AC-085).

Browsers that do not show the native confirmation, notably Safari on iOS, show none on reload or close: the page unloads, the answer is lost and no confirmation is stored, as for AC-033. The application's dialog does not depend on the browser and is always shown.

**Verification:** End-to-end test in a browser that supports the native confirmation, for Colombia and Chile, with the payment answer delayed: reload with stay and with leave; browser back with stay (the confirmation then appears) and with leave (the summary is shown again unpaid on return); unit test (the summary reports something to lose only while processing; an answer after leaving is ignored; an answer while the dialog is open is applied).
